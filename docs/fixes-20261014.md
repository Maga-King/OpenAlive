# 2026-10-14 兼容性修复

## 壁纸应用流程

魅族、Vivo、小米的应用按钮每次都进入系统选择器，避免仅检测桌面已有同一服务就跳过锁屏应用。按顺序尝试指定动态壁纸预览、动态壁纸列表、系统壁纸入口、系统壁纸或主题应用的普通启动入口。

取消选择器不提交编辑内容。普通壁纸入口可能不提供可靠的应用结果，返回时同时核对实际组件和壁纸 ID 的变化；Android 14 及以后也检查独立锁屏。AOD 配置仍要求锁屏实际使用 OpenAlive，独立静态锁屏不能仅因为桌面使用 OpenAlive 就通过检查。

## 魅族动态壁纸衔接

ColorOS 的息屏、遮挡页面、指纹直达事件原本已由各系列共用。Cosmic、Phoenix 和气泡渲染器的缺口是隐藏后仍按墙钟推进过渡，恢复时可能跳到终点。现在使用可暂停时间轴，隐藏期间不消耗过渡时长，恢复和反向切换保留当前插值；保持原版曲线、时长、配色与构图。

显示器在 DOZE、ON 等状态间切换时，全部渲染器重新挂接帧回调，避免等待属于旧显示状态的回调。

仅在 `3B1F4UE5MS13HQRR` 上运行独立测试包：覆盖 23 款、明暗模式、保持锁屏开关、六向切换、暂停恢复和中断反向，302304 次参数断言通过。测试包随后卸载，没有修改用户壁纸或电源设置。此结果验证实际 Android 插值器和生产动画参数，不代替 SystemUI、指纹和真实桌面遮挡的视觉验收。

## Vivo 默认色彩

默认雪山三张、液态和闪卡照片均嵌入 Display P3 ICC。素材字节不变，未增加饱和度或对比度。重新反编译仓库内原版 APK 确认：`render.e.loadTexture(Bitmap)` 直接调用 `GLUtils.texImage2D`，没有传递 Bitmap 色域；原版 `T3.e.onHandleSetWideColorGamut` 使用 `X5.a.p0` 启用宽色域，文件解码通过 `inPreferredColorSpace=DISPLAY_P3` 转换自定义照片。旧宿主上传原始 P3 数值，却使用普通 EGL 窗口，导致颜色解释错误。

Vivo 窗口现在优先使用 `EGL_EXT_gl_colorspace_display_p3_passthrough`。引擎输出已编码的 RGB，普通 `DISPLAY_P3` 表面会再次执行传递函数；实机色块检查曾出现应为 107 的红通道变成 174，因此采用 passthrough 避免二次 gamma 编码。

上传照片前按 ICC 转换为实际窗口色域：P3 原图在 P3 窗口保持原值，sRGB 图片转换为 P3。蒙版保持原始数值。不支持扩展或窗口创建失败时回退普通窗口，并明确转换到 sRGB。编辑器窗口也声明宽色域。视频使用原引擎的 sRGB 到 P3 开关，已经转换的照片关闭该开关，避免重复转换。

仅在指定主力机运行独立 Vivo 测试包，均得到 `VIVO_SCENE_OK`：五张默认照片 ICC、sRGB pbuffer 和实际 SurfaceTexture 窗口的 P3/sRGB 色块（与 Android ColorSpace 转换比较）、三类壁纸及 36 种液态/闪卡效果与区域组合、传感器暂停恢复和息屏状态。另在 sRGB 与 P3 窗口分别验证三图导入、持久化、封面保留、超限拒绝以及视频播放、裁剪、暂停恢复。测试包已卸载；其他 ROM 的系统合成和物理屏幕色彩模式仍可能影响最终观感。
