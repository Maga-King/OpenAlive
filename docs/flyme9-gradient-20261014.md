# Flyme 9 渐变恢复

来源是系统公共组件 1.8.15 中的 `com.meizu.flyme.sdkstage.wallpaper.gradient`，三款为大漠、极光、远海。原始着色器和列表图片直接取自 APK，配色按原渲染器绑定关系提取；来源及文件 SHA-256 见 `app/assets/gradient/source.json`。

此前实现虽然能编译，但曲线系数只是常数、四个顶点无法表达内部曲线、配色数组与 uniform 上传顺序不一致、顶点属性位置被硬编码，并把纳秒绝对时间反复累加为动画增量。暂停还会永久停止动画，深色参数也没有上传。

现在使用自然三次样条（两端二阶导数为零），归一化 x/1080、y/2340，上传每段的四个多项式系数。算法为独立的三对角求解，没有引入 Apache Commons Math 运行依赖。六条曲线按原始 b/f/g/d/c/e 依赖顺序更新，保留 30 秒初始形态混合周期及正弦参数。网格使用原厂 100 列，按链接后的实际属性位置绑定。配色统一命名顺序，深色主题使用原 shader 的亮度/对比度处理。计时仅累计可见帧，隐藏/恢复重置基准而保留当前形态；是否持续运动沿用公共 RenderLoop 的用户设置。

原始 DEX 进一步确认：横屏 mesh 高度为长边，相机高度为 `h*h/w`，因此 UV 纵向裁切比例为 `(w/h)²`；色彩时间不乘减速系数，只有形状使用钳制后的帧差乘速度。这两处也按原厂行为保留。

在用户指定备用机 `10.101.1.221:5555`（Adreno 725）运行独立测试包：三款 × 浅/深色 × 横/竖屏，读取初始、8 秒、25 秒、30 秒及跨周期 GPU 输出，与 CPU 计算的配色及曲线位置比较；验证全帧不透明、样条 C0/C1/C2 连续及自然边界、30 秒形状返回、隐藏时间不累加、恢复继续动画、独立颜色时钟与有限形状运动可停止。测试通过，测试包自动移除；未更改主应用数据。图像在 `build/gradient-render/`，测试报告在 `result.txt`。像素参考复用生产曲线系数，不能单独证明六条动画公式；公式另对照原始 b–g 类检查。

原包库存核对：用户指定的园蓝、梅洛、金杏、青提已作为 ID 16–19 独立保留，未替换新版同编号配色；另外三款渐变为 ID 301–303。原包还有尚未接入当前动态壁纸列表的浪流、深潜、涟漪三款视频，以及 Stereo V4/V5/V6 三款深度壁纸。Alive 照片是功能入口，当前已有 ALIVE 照片编辑体系，不应仅因缺少同名列表项就断言整项缺失；Flyme 9 版本的每个效果尚未逐一对照。

复现命令：

```powershell
python tools/check_gradient_render.py --serial 10.101.1.221:5555
```

测试编译原始生产类和 shader，以现有 `build/release/classes` 提供其余壁纸类型的编译期符号；需先有一次完整构建。完整 APK 的页面交互与安装验证另行记录，独立 GPU 测试不代表指纹 Hook 已实测。
