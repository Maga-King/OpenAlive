# Vivo media and mask editors

The raster editor has three ordered positions: 封面图片/视频, 光栅图片/视频1, 光栅图片/视频2. Each independently accepts a picture or looping video, with its own crop and quarter-turn rotation. Swapping positions moves the media and its transform together. Batch picture selection replaces one to three positions in picker-returned order; remaining positions stay unchanged. 感应视频 retains its original native seeking controller and separate entry. Imported files are immutable private snapshots; looping clips keep a poster and render into stable native 2D textures. Both stills and every decoded video frame use the same rotation and crop. Native tilt-video can also use an independently edited still or looping cover.

Research: LiveWallpaperBox 7.0.1.02 actually sets `RasterRenderPreEditImp.PIC_MAX_LENGTH=4`. `PanelPicSelectView` supports thumbnail selection, addition, deletion and drag ordering. `ThemeEditInterfaceWrap.doChooseImages` delegates to the theme editor (102); `setRasterImageIndex` and resource changes delegate to the picture editor (103). The complete cropping UI is in that external host, not this APK. OpenAlive intentionally uses the three positions requested by the user.

0.4.27 fixes an import snapshot bug: a non-raster photo import populated `photos` while leaving `rasterVideos` empty. Parsing that snapshot padded the video list, so the mask loader's equality guard rejected every result until the Activity was reopened. Imports now fill the parallel list, and serialization consistently emits one video entry per photo. Abandoned mask loads also restore the Apply button. Continuous crop requests use a synchronized latest-value mailbox; final release flushes before preferences are saved. Only that final crop recalculates the liquid distance field/lattice; the in-memory scene crop is updated so saving it does not destroy the renderer.

Liquid and Flash custom ranges now open an actual photo-coordinate mask editor with brush, eraser, brush size, bounded undo, and PNG save. Subject/background use offline U2NetP salient-object segmentation, with optional crop selection and manual correction. A missing custom-photo subject opens recognition automatically. The model uses 320x320 RGB normalization with the upstream mean/std and output min/max normalization. Inference runs on a worker, serializes model sessions, disables retained CPU arenas, and cancels the active ONNX run when the dialog closes. Leaving the editor or changing its photo cannot apply an old result to a new snapshot.

The native contract is opaque grayscale RGB: white selects the effect, black excludes it. Background pixels are the exact RGB inverse of the subject. Liquid's original `Q3.c.k` then thresholds and constructs a distance field; the final two distance fields are consequently not arithmetic complements. No mask is converted through a display color space.

Dependencies are pinned in `vendor/onnxruntime/source.json` and `app/assets/vivo/models/source.json`. ONNX Runtime Android 1.23.2 has 16KB PT_LOAD alignment for both arm64 libraries. U2NetP is the rembg-distributed conversion whose MD5 matches the upstream rembg v2.0.67 checksum. Its originating U-2-Net repository publishes Apache-2.0 licensing and links the pretrained U2NetP weights; there is no separate weight-license file in that upstream publication. The model is not modified. Runtime MIT/third-party notices and model license are included with the application assets.
